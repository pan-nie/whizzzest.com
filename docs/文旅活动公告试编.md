## 转载和公开发布边界

- **原文链接与事实摘要。** 单条用自己的话写日期、地点、活动名称、预约或改期等已核实事实，来源旁附直达链接。单纯事实消息属于《著作权法》第五条列明的范围。政府网站上的文章、海报和照片需要分别判断权属与许可，公开可读本身不构成授权。 [《著作权法》第五条、第十条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)
- **全文、配图及英文译文。** 首版保持纯文字。转载原稿、原图、海报、文章截图、视频或发布全文译文前，向权利方核实并留存许可，写明可用的文字或素材、发布渠道、期限、署名和商用范围。若制作英文卡片，从核准后的事实字段另写，原文仍链接到发布方。 [《著作权法》第十条、第二十四条、第二十六条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html) · [国家版权局关于网络转载的通知](https://www.cac.gov.cn/2015-04/22/c_1115052967.htm)
- **新闻信息服务许可。** 版权许可、稿源资格和本站服务许可分别核实。以「万载」检索 2025 版公开稿源名单，未检出对应条目。国家网信办的 2026 年 9 月底许可信息索引指向江西公布渠道，本次未核实对应账号的最新许可范围。上线前可将具体栏目范围和样稿提交属地网信部门核实。如果涉及受许可管理的新闻信息服务，按确认的许可和稿源要求办理。首批编辑范围限于游客行程相关的活动安排、变更和场馆开放。 [《互联网新闻信息服务管理规定》第二条、第五条、第十五条](https://www.cac.gov.cn/2017-05/02/c_1120902760.htm) · [2025 版稿源名单](https://www.cac.gov.cn/rootimages/uploadimg/1753168169303989/1753168169303989.pdf) · [国家网信办许可信息索引](https://www.cac.gov.cn/2026-10/23/c_1794509036894710.htm)

## 首版页面和后台

1. **前台。** `/news/` 使用现有站点布局，按「即将举行」「场次变更」「历史公告」展示。卡片依次显示状态、时间、地点、简短事实和原文入口。没有确认的未来场次时，显示「暂无已核实的近期活动」。有有效的焰火场次或变更时，可从观赏点页 `/spots/` 链入。英文版发布时使用同一条活动记录，由编辑核对英文标题和摘要，确保两种语言的时间、状态与来源同步。
2. **后台。** 复用管理员入口和 D1。编辑贴入单篇链接，填写来源方、原文标题和发布日期、活动时间及地点、预约入口、活动状态和核验日期。允许时间、票价等未公布的字段留空。保存草稿后人工复核发布，更新或撤下时保留审核人、时间和对应来源。前台只读已发布记录。 [现有图库后台](../admin/gallery.js) · [新增功能检查单](加功能检查单.md)
3. **去重和更新。** 同一篇稿件出现在多个栏目时保留一个活动入口。用活动届次、具体场次和地点识别同一活动，改期时更新原条目并保留原定时间和变更依据。多场演出逐场存时间。场次到期后移出近期列表，馆舍开放信息按确认有效期维护。活动前一天复核时间、地点和预约，焰火等易变场次在当天再核一次。来源失效或说法冲突时进入待复核，暂停展示受影响的近期信息。
4. **采集。** 先手动维护少量来源，观察更新频率、原帖能否稳定打开以及频繁变更的情况。政府门户能用浏览器列表和站内搜索找稿，本次未核实可供本站长期自动调用的官方订阅或接口许可。后续优先接发布方同意使用的订阅、公开接口或供稿渠道，抓取只生成待审草稿。失败时保留上次成功记录和错误原因，有限次重试，再转人工核查。

首轮验收用古城四场演出测试逐场到期，用龙湖晚会测试延期前后的场次，用图书馆闭馆和开馆记录测试旧告示退出当前提示。接入供稿时可再用花炮文化节测试跨栏目去重。公开首发时用新近核实的场次填充「即将举行」。

## 自动采集与更新计划

先用一个已确认使用范围的官方订阅、公开接口或供稿渠道试点。登记来源的主体、可用字段和频率。定时任务优先按来源提供的游标或缓存验证信息增量读取。公众号可以继续由编辑提交原帖链接，直到有合适的供稿方式。

用来源文章编号或规范化后的原文 URL 消除重复采集，再按活动届次、场次和地点匹配已有公告。保存来源发布日期、内容指纹和最近一次成功核验时间。同一篇内容重复出现时不新建记录。原文更正、改期与取消进入现有公告的待审版本，由编辑核对差异并确认发布。多个来源对时间或地点说法不一致时，保留各自链接供编辑判断。

遇到请求失败先退避重试，连续失败时提示人工核验。来源暂时不可访问或在列表中消失时保留记录，编辑根据主办方确认决定是否下线。公开版继续遵循现有审核流程，归档继续按场次结束时间计算。

## 本地试跑

主站地址为 `/news/`，后台入口为 `/#/notices`。保存草稿后打开「审核」，核对场次与原公告，再点击「确认发布」。已发布公告通过「变更场次」保存新的待审版本。前台在最后一场结束后自动将记录显示在「历史公告」。填了具体结束时间的场次以该时间为准，仅填日期或未填结束时间的场次以当天北京时间结束为准。

`npm run build` 后运行 `npm run test:activity-notices`，会在独立的本地 D1 中用七条样稿复测。浏览器试跑的七条已审核数据保存在工作区的 `.wrangler/activity-notices-local`，重新启动主站和后台时可以共用此目录。主站在下列命令启动后可从 `http://127.0.0.1:8796/news/` 查看。

```sh
npx wrangler dev --local --host 127.0.0.1 --port 8796 --persist-to "$PWD/.wrangler/activity-notices-local"
npx wrangler dev --config admin/wrangler.jsonc --local --host 127.0.0.1 --port 8797 --persist-to "$PWD/.wrangler/activity-notices-local"
```
